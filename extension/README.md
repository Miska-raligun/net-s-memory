# 互联网记忆 · 存档与见证浏览器扩展

## 主线：存下原文，发现删除，多人见证（无任何自建服务器）

- **存档本页**：抽取正文（公众号 `#js_content` 等平台容器 → Readability → body），
  按 `nsm-text-norm.v1` 规则规范化后计算 SHA-256。正文、可视区截图、原始 HTML
  只保存在本机（`unlimitedStorage`）。
- **比特币时间戳**：对正文哈希做 OpenTimestamps 锚定（只发送加盐哈希）。下载的正文 +
  `.ots` 可直接用 `ots verify` 独立验证。
- **Internet Archive**：可选，同时让 archive.org 抓一份第三方快照。
- **删帖识别**：公众号 / 微博 / 知乎 / 抖音 / B 站的删除、屏蔽页文案，以及 HTTP 404/410。
  原文被删后，徽章变红，并提示本机是否存有副本。
- **发布见证**：显式操作。kind `1909` 的 Nostr 事件，标签 `r`=规范化 URL、
  `x`=正文哈希。短正文内联在事件里，超长正文走 Blossom。验证时会重新计算哈希，
  不一致直接拒收。截图和 HTML 默认不上传，因为可能带有你的登录信息。
- **查找其他报道**：在你自己的浏览器里打开 Google 或必应国际版（`ensearch=1`）的结果页，
  由内容脚本读取结果，**不调用任何搜索 API**。默认隐藏境内来源。
- **我的存档**页：列表、详情、哈希自校验、导出 JSON / 正文 / HTML / `.ots`。
- **网络见证**（用户点击后才查询，因为查询会让中继知道你在看哪个链接）：
  按 `#r` 拉取 kind 1909 见证和 kind 1910 观察，在后台逐条验签并重新计算哈希。
  然后按正文哈希分组：每个版本显示几个不同密钥见证过、几个是你关注的人、
  是否与本机副本一致。版本不一致时会明确提示。
- **本地信任列表**：可以在见证人旁边点「信任」并写备注，也可以在设置里粘贴 npub、
  或者导入某个人的公开关注列表（只读取）。列表只保存在本机，从不发布。
  被信任的见证人显示 ✓ 和你写的备注，版本按「信任人数」优先排序。
  另有一个开关，可以把你这个 Nostr 身份在其他客户端里公开关注的人也一并计入。
- **检查更新**：每天最多一次向 GitHub Releases 查询最新版本，请求不带 cookie，设置里可以关闭。
  有新版本时图标显示蓝色「↑」（如果同时有新删除的提醒，优先显示删除数量）。
  弹窗里给出下载链接、SHA-256 和三步升级说明。扩展只提示，不会自动下载或安装。
- **导入他人副本**：后台按事件 id 重新取回并校验；超长正文从 Blossom 取回后核对哈希。
  导入的副本标注「他人见证」，不能再以自己的名义发布见证。
- **删除观察**：在删帖页上手动发布 kind 1910 事件（`r`=URL，`s`=状态，`x`=你最后见过的
  正文哈希），把「何时消失」和「消失的是哪个版本」关联起来。
- **定期回访**：用 `chrome.alarms` 每小时检查一次到期的链接。回访按存档后 1 小时、6 小时、
  1 天、3 天、7 天、30 天、90 天退避，请求不带 cookie。遇到反爬验证页、5xx、429 时
  记为无法判断，留到下次再查。微博、知乎、抖音、B 站这类前端渲染的平台只在你亲自访问时判断。
  发现被删时，扩展图标显示红色数字，弹窗里列出所有已消失的链接。

一个**去中心化、零自建服务器**的浏览器扩展：在任意新闻正文页实时显示信源可信度信号。
评估调用**你自己的 LLM key**在客户端完成，未来通过 **Nostr** 共享社区签名存证——
全程不依赖任何 net-s-memory 服务端。

这是 net-s-memory（互联网记忆）的「插件化 / 去中心化」分支，复用其四信号可信度模型、
信源信誉种子表与可信度卡片视觉。

## 状态：Phase 1–3（本地评估 + Nostr P2P 协同）

- ✅ Readability 抽正文 → 客户端调用户 LLM key 现场评估
- ✅ 四信号打分（来源信誉 + LLM 一致性 + 多源印证占位 + 社区存证），镜像后端 `credibility.py`
- ✅ 内置域名信誉种子表（先验）+ 注册域后缀匹配
- ✅ 页面右下角徽章（Shadow DOM 隔离）+ 展开可信度卡片
- ✅ popup（看当前页评估）+ options（LLM key / Nostr 身份 / 中继）
- ✅ 24h 本地缓存，断网/无 key 时降级为「仅来源信誉」
- ✅ **Phase 2/3 Nostr**：secp256k1/schnorr 身份；可信度断言签名为
  参数化可替换事件（kind 30909，按归一化 URL 寻址）发布到公共中继；
  订阅他人断言、客户端验签、按 NIP-02 关注图谱加权（信任网络）
- ✅ **Phase 4 OpenTimestamps**：把评估承诺哈希提交到公共日历服务器、
  锚定到比特币；「锚定到比特币 / 刷新锚定」按钮显示区块高度。
  `.ots` 二进制格式**自研零依赖实现**（Web Crypto + fetch），并在单测里
  与官方 `opentimestamps` 库做了逐字节交叉校验（运行时不打包该库，
  避开 node crypto/fs/bitcore）。锚定证明可嵌入 Nostr 事件一并传播。
  完整无信任的比特币区块头校验交给官方验证器（界面提供链接）。
- ✅ **Phase 5 冷启动桥接**（后端，可选）：`python -m app.bridge.run` 把
  net-s-memory 已有的签名 analysis 重新发布成 Nostr 存证（用桥接身份签名），
  让新装扩展的用户一上来就能看到种子数据而非空网络。这是唯一碰后端的部分，
  完全 opt-in（不配 `NOSTR_BRIDGE_SECKEY` 就什么都不做），且 URL 归一化/寻址
  与扩展逐一对齐（见 backend/tests/test_bridge.py 的 parity 测试）。

隐私：正文只发给你在设置里填写的 LLM 端点；评估只在你点开徽章面板时触发；
**背书（发布到 Nostr）是显式操作**，默认不向任何第三方广播浏览行为。

## 开发

```bash
npm install
npm run dev        # Vite + CRXJS，开发时热重载
npm run typecheck  # tsc --noEmit
npm run test       # vitest 单测（33 个，CI 跑这个）
npm run test:it    # 起一个进程内 NIP-01 中继，跑真实 publish→query→trust 全链路
npm run build      # 产出 dist/（可加载的扩展）
```

### 在浏览器加载

1. `npm run build`
2. Chrome → 扩展程序 → 打开「开发者模式」→「加载已解压的扩展程序」→ 选 `dist/`
3. 打开扩展设置，填入你自己的 LLM key（DeepSeek / SiliconFlow / OpenAI / Anthropic 任一）
4. 打开一篇新闻正文页，右下角出现可信度徽章，点开即可评估
